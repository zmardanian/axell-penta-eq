# Design decisions (each backed by a measurement)

| # | Decision | Why (measured) |
|---|---|---|
| D1 | Filter core = matched 2nd-order sections (impulse-invariant poles, magnitude-fitted numerators) **plus a minimum-phase correction FIR** (256 taps at 44.1/48 kHz) | A single matched biquad missed ±0.1 dB on 15–25 % of a realistic grid at 44.1/48 kHz (worst ≈ 1–3.8 dB, resonant shelves and wide/high bells). With the correction every tested case is < 0.0001 dB, and a minimum-phase FIR adds no latency. Prototype study: `tools/proto`, `docs/research/dsp-literature.md`. |
| D2 | Every section realised as a TPT state-variable filter; per-sample interpolation of **g, k and the output mix** (a1..a3 derived per sample) | Interpolating the derived a1..a3 can leave the valid parameter manifold; the Console E↔G switch produced a +11 dBFS burst in the click test. With g/k interpolation every intermediate filter is a stable SVF: click test −75 dBFS worst. |
| D3 | Passive Tube LF: boost = 2nd-order shelf, midpoint 2× the selection, Q 0.8; atten = 1st-order shelf, midpoint 3.5× the selection | Calibrated against published behaviour (SOS: boost ≈ +14 dB, atten ≈ −18 dB, combined "resonant shelf" with a dip up to 8 dB). Measured: boost 10 alone +13.6 dB @ 30 Hz (60 Hz setting); boost 10 + atten 5: +5.0 dB @ 30 Hz, dip −3.5 dB at 3.8×; both at 10: dip −7.8 dB (DspTests H). |
| D4 | Natural Phase = complex correction FIR (analog/digital) with D = 128 samples at 48 kHz, as a 2×2 matrix in stereo | D = 64 left 0.15–0.18 dB error on 96 dB/oct cuts; D = 128 gives ≤ 0.05 dB on the whole grid. A matrix (L←L, L←R, R←L, R←R) keeps any mix of L/R/M/S bands exact with one latency (cascaded L/R and M/S FIR stages would double it). |
| D5 | Linear Phase = 2×2 zero-phase FIR matrix, Tukey window (flat, 1/8 raised-cosine ends), uniformly partitioned (P = N/32) | Kaiser β = 6 smeared a 100 Hz Q 4 bell by ~2 dB at Medium. Tukey keeps narrow low bands; accuracy is then limited only by FIR length (Medium: f ≥ max(100 Hz, 40·Q); High: f ≥ 10·Q), measured ≤ 0.1 dB within those limits. |
| D6 | Coefficient ramps stop exactly at the end of their control block | Without it the increments kept running whenever no new target was set (found by the Console switch test: output grew to +3.7 and then to infinity). |
| D7 | Structural band changes (type, slope, placement, mode, add/remove): fade out 8 ms → switch → **20 ms silent warm-up** of the new structure on the real input → raised-cosine fade in; warm-up length rounded to whole control blocks | A cold filter fading in on a running signal gave a −25 dBFS HF burst; with warm-up −133 dBFS. Non-block-aligned warm-up made the output depend on host block size. |
| D8 | Stereo bands always process in L/R | A Stereo band processing in whichever domain the buffer happened to be in received M/S signals with L/R state when a neighbouring band switched to Mid (−25 dBFS burst). |
| D9 | Dynamic bands: fast region detector (~3 cycles), user attack/release smooth the **gain change** in dB per control block | Attack/release then mean what they say: measured 63 % times 30.2 ms / 154.8 ms for 30 / 150 ms settings (±20 % target). |
| D10 | Below 0.025 rad/sample (190 Hz at 48 kHz) the peak fit uses the matched-Z mapping | The closed-form peak fit squares sin²(w0/2) ≈ 5e-6 and loses precision; matched-Z is exact far below Nyquist. (The apparent 30 Hz Q 12 failures turned out to be measurement artefacts - impulse truncation and bin interpolation - fixed in the test.) |
| D11 | Natural-phase correction: a bin where the digital response is singular (zeros at DC from a high-pass) gets no correction | 0/0 at DC turned into NaN with the Inductor's 2 Hz "off" high-pass (fuzz test). |
| D12 | Session state = binary ValueTree with the exact plain value per parameter; restore searches the neighbouring floats for an exact normalised pre-image; the DSP reads the parameters' own values, not APVTS's cache | XML text and plain→normalised→plain on skewed ranges lost the last bit; APVTS's cache ignores "approximately equal" updates. Now a reopened session is bit-identical (PluginTests). |
| D13 | Undo/redo = snapshots of user edits only (gesture start, preset load, A/B), not APVTS's UndoManager | APVTS records every parameter change, including host automation, into the UndoManager. |
| D14 | Host bypass = engine with Mix 0 (latency-aligned dry, bit-exact) | Keeps the host's delay compensation correct while bypassed (PluginTests: bypass output = input delayed by the reported latency, exact). |
| D15 | Oversampling default 1x | Zero Latency stays zero latency by default; the drive curves are low-order, 2x/4x are available for heavy drive (FIR halfbands from Duo Vocal Comp, ≥ 100 dB rejection). |
| D16 | Auto Gain is static (pink × K-weighted power of the analog curve) | Never pumps; measured loudness match within ±0.4 dB on pink noise for typical curves (DspTests I). |
| D17 | Preset output trims set from measurement | All 40 presets within ±0.05 LU of bypass on pink noise (−18 dBFS, BS.1770 K-weighting); test gate ±0.1 LU (was ±0.5 LU, which let the D18 change shift seven presets by up to 0.36 LU unnoticed; re-trimmed). |
| D18 | Butterworth pole pairs at (2k+1)π/2n for even orders, (k+1)π/n for odd orders | The even-order formula had been used for every order. A 3rd-order cut's pole pair got Q 0.577 instead of 1.0, so 18 dB/oct cuts and the Inductor/Console HPFs were −7.8 dB at the corner, not −3 dB. It went unnoticed because the DSP suite compared the engine with its own model; the independent audit (tests/independent) found it. Section L of the suite now checks every slope against the exact Butterworth curve. |
| D19 | Generic (shelf/tilt) sections: compute both the 3-point fit and matched-Z, keep the one with the smaller error at the pole/zero natural frequencies, w0, their mean and an octave outside (≤ 0.85π) | Between its fit points the 3-point fit missed resonant shapes. Shelves and tilt with Q 2–5 were up to 6.6 dB off and Q 5–24 up to 27 dB, beyond the ±12 dB that the correction FIR repairs. With the selection, Q ≤ 5 is within 0.006 dB at every rate, and Q 5–24 within 0.06 dB at ≥ 88.2 kHz or with 2x oversampling. At 44.1/48 kHz without oversampling, about 3 % of Q > 5 shelves (resonance near or above Nyquist) remain off; documented. The score costs a few µs per design. |
| D20 | After a phase-mode / OS / quality switch, the output stays muted for the new latency + 20 ms before fading in | Every delay line restarts empty. With a 20 ms warm-up, switching to Linear Phase (90 ms latency at Medium) faded in on silence and the delayed signal then started abruptly. That was a click (−8.6 dB HF burst, independent audit); now −105 dB. |
| D21 | Float one-pole smoothing of the gains, Mix and Auto Gain snaps to the target once a step no longer changes the value | The step (t − v)·a drops below half an ulp 1e-5…1e-4 short of the target, so gains stayed up to ~0.0005 dB off for good. Now exact (suite section L, audit). |
| D22 | A *user* change of a band's type resets a neutral Q: cuts 0.71, other types 1.0. A tuned Q is kept, and host automation or session restore never touch Q (detected through the parameter gesture, which only UI edits send) | A band switched to Low/High Cut kept Q 1.0: a +2.2 dB bump at the corner with the default 24 dB/oct slope, although the control says "0.71 = no peak". |
| D23 | The session state also holds the A/B pair: an `AB` child with the active slot and the inactive slot's parameters (exact plain values, like the state itself). A state without it (older builds) means slot A active and slot B empty, as in a new instance | Only the audible slot was saved, so a reopened project lost the other comparison and always showed A (found by an external review after v1.0.0). Slot snapshots now carry the exact values too, so A/B round trips are bit-identical (PluginTests). |
| D24 | **Latency handshake.** The engine never plays a configuration whose latency the host does not compensate. A latency-changing switch fades out, then posts a request (an atomic word: state, sequence, latency); the wrapper's 50 Hz timer claims it (compare-and-swap posted → reporting), tells the host (VST3 `restartComponent`, synchronous on the message thread) and acknowledges; only then the engine applies the configuration and fades in after its warm-up (latency + 20 ms + one host block). If no report comes within 0.5 s the engine withdraws the request by compare-and-swap (posted → withdrawn) - a claimed request cannot be withdrawn, so a report can never land after the engine gave up - and fades the **old** configuration back in, which is what the host still compensates; it retries once the timer's heartbeat shows the message thread running. The latency is published through an atomic. Offline renders switch at once (deterministic) | 1.0: a plain `int` shared by the audio thread and the timer (a data race), and the engine faded in after latency + 20 ms whether or not the host knew (~3000 misaligned 16-sample windows over 8 switches through a live VST3 host). 2.0.0 waited for the report but resumed the new configuration after 0.5 s without one - misaligned if the host was never told. 2.0.1: in no case does audible output run under a compensation the host was not given (PluginTests: no response → old mode, aligned, request withdrawn; retry; a claimed report is never abandoned; audit live-host check 0 misaligned windows). |
| D25 | **Near-Nyquist realisation.** A section whose classic matched biquad misses its analog curve by more than 0.5 dB across the audio band (only possible when a resonance, corner or centre lies near or above Nyquist) is realised as two cascaded biquads fitted by Levenberg-Marquardt to the analog log magnitude up to 20 kHz. Parametrisation: c2 = R² tanh v2, c1 = R tanh v1 (1 + tanh v2) - all polynomials with roots inside radius R (poles 0.999; zeros 0.999 for cuts, which are inverted). Structural zeros stay exact (high-pass at DC, notch on its centre, band-pass at DC). Above 20 kHz a one-sided bound (≤ analog + 3 dB; a floor for cuts). Cold fits start from the classic, matched-Z and two bilinear designs, then add a second stage from an exact pole/zero cancellation; candidates are scored on a dense grid. A changing section continues from its previous fit (one Gauss-Newton step per control block); the hardness check of a classic section repeats every 32 redesigns. Notch and band-pass are no longer clamped at 0.49 fs | At 44.1/48 kHz, 1x: Q 5-24 shelves/tilt were off by up to 26 dB (beyond the correction FIR's ±12 dB), notch/band-pass above 15 kHz up to 25 dB, also with the clamp. A single fitted biquad still left up to 5 dB (and without the bound, a pole ran to z = -1: +138 dB at Nyquist). Measured after: dense random maps (shelf/tilt any Q, notch, band-pass, bell, cut, 9-30 kHz) all within 0.07 dB in Zero Latency and Natural Phase; independent audit 0 failures with no exemptions. Cost: typical sessions unchanged (benchmarks within ±0.03 %); 4 fitted bands at 48 kHz, 2 of them dynamic with moving gain: 4.2 %. |
| D26 | **Natural Phase correction, low-level gaps filled smoothly.** Where the analog target is below -60 dB (fully below -90 dB) the correction matrix is blended towards an interpolation (log magnitude, unwrapped phase) between the nearest valid bins, held at the ends, instead of towards the identity | Steep, narrow band-passes (8 sections, Q 12) run a few degrees off the analog phase in their 25 Hz passband; fading to the identity in the skirts turned that into a phase step the 2.7 ms window could not hold: up to 0.43 dB / 5.4° off. Now every case ≤ 0.05 dB; Natural Phase phase error vs analog in the audit 2.1° → 0.7°. |
| D27 | **Correction above 20 kHz held.** Both correction designers hold their target (log magnitude; complex matrix) at the 20 kHz value from there to Nyquist | The near-Nyquist realisations are deliberately free above 20 kHz; a correction trying to "repair" that region hit its ±12 dB clamp and the step spilled back below 20 kHz (3.6 dB at 20 kHz on a notch above Nyquist). |
| D28 | **Crossfade instead of coefficient interpolation when a realisation jumps.** When a section switches between the classic and the fitted realisation, or a fit restarts, the new realisation runs on the same input with fresh states, silent for 32 control blocks (~11 ms), then crossfades in over 32 blocks while the old one keeps playing (a classic old realisation keeps following the target; a fitted one holds). Smooth changes still ramp the coefficients | Interpolating the coefficients of two very different filters that hold signal clicked: a 21 kHz Q 8 bell gain sweep at 44.1 kHz gave a -23 dBFS HF burst. With the crossfade: -88 dBFS (v1.0: -128); a near-Nyquist notch sweep -91 dBFS; a resonant high shelf sweep -92 dBFS (v1.0: -42). |
| D29 | **Spectral dynamics** = STFT detector (Hann, N = 1024 at 44.1/48 kHz, scaled with the rate, hop N/4) → per frequency: the loudest level within ±2 bins, the band's threshold / ratio / range / attack / release (6 dB knee), × the band's own region weight (its shape at +12 dB, normalised), [1 2 1] smoothing → **minimum-phase FIR** (real cepstrum, N/2 taps × oversampling factor) after the band's filter, in its L/R/M/S domain, crossfaded per hop; hops tied to the absolute sample position; every band keeps its FIR history current | Zero added latency in every phase mode (an STFT resynthesis would add a frame). Levels widened, not gains: widening the gains spread a 220 Hz band's action an octave down (two bins = 94 Hz). History kept warm: a band switched to Spectral while acting clicked at −18 dBFS from stale history; now below −60 dBFS. Measured: loud in-band tone −11.8…−11.9 of −12 dB, quiet in-band tone 0.000 dB (broadband: −8.3), identical at 1x/2x/4x and in all phase modes; ≈ 0.6 % CPU per acting band at 48 kHz. |
| D30 | **Workflow tools** in the graph (multi-selection, frame drag on empty space, group drag with equal ratio / dB, keyboard, invert, copy/paste via a process-wide clipboard, note readout + snap, Alt+click peak grab refined by parabolic interpolation on the FFT bins, freeze) and **Gain Scale** (0–200 %, applied in CurveModel so audio, display, auto gain and Linear Phase agree) | Studied in docs/research/workflow-study.md. Frame drag needs no modifier: the drag distance tells a click (add a band) from a frame. A burst of key repeats is one undo step. Peak grab on the 1/6-octave display grid was 4.5 % off on a 3 kHz tone; on the bins, exact. |
| D31 | **Draw / Match fit bands with one fitter** (CurveFitter): greedy placement on the largest smoothed deviation (bell with Q from the half-height width; a shelf when the deviation runs off an end of the band), then joint damped Gauss-Newton over log f, gain, log Q of all bands on the analog curves. Match uses the level-normalised (100 Hz–10 kHz mean removed), smoothed, amount-scaled and clamped difference of two captured 1/6-octave power spectra; the reference is shared across instances of the process | Recovers known band sets exactly (4 bands, 0.000 dB RMS); freehand curves ≈ 0.04 dB RMS with 11 bands in 25 ms on the message thread; in the plugin test a drawn +6 dB bump is rebuilt to 5.98 dB and a match curve to 0.01 dB. |
| D32 | 2.0 parameters (per-band Dynamic Mode, Gain Scale) are **appended** to the table with version hint 2 | Earlier sessions, presets and host automation keep every parameter ID; a 1.0 session opens with Broadband / 100 % (PluginTests). |
| D33 | 3.0: detector source **Ess** = the dynamic band's own level × Axell Velvet 3.0's LIVE sibilance probability (axell-core, causal network, instant up, 20 ms down); the source list gains one entry at its end | A dynamic band keyed by its own level is a classic split-band de-esser: it also cuts bright vowels, stops and other fricatives. On Velvet 3.0's benchmark (59 takes of voices no network trained on, as recorded, Penta rendered black-box through the independent VST3 host; `research/bench_ess.py`), at equal remaining harshness (8.6 %): collateral on vowels +0.07 dB (SELF key +0.29), other fricatives +0.11 (+0.28), stops +0.22 (+0.50). A bell at 6.5 kHz with range -12 dB does not reach 5.2 % harsh with ESS (it cuts only on esses and only that much); for deeper de-essing Velvet itself is the tool (+0.01 dB on vowels there). DSP suite: esses -7.8..-8.0 dB (SELF -8.0), vowels between them -0.03 dB, a bright vowel -0.05 dB (SELF -12.0). Limit: the network judges esses re the voice's own treble, so on a voice with very strong steady treble it cuts less. Existing choice indices are unchanged, so sessions and presets (they store the index) open as before; a host automation lane drawn on a band's Detector in 2.x (normalised values) would point at shifted sources - the source is a setup choice, not something to automate, so the list was extended rather than adding twelve parameters. |
| D34 | 3.0: **Axell's Dojo look** (axell-core BrandTitle: emblem, brush title with the seal 五 "five", the plugin's own umber ground: every surface colour from one hue, 42 degrees) | Text, band colours and meters unchanged, so every reading keeps its contrast. |
